Executive Research Summary

Quantifying & Eliminating Algorithmic UI Defaults

"AI Slop" in web design is not an inherent limitation of artificial intelligence, but the direct result of unconstrained statistical inference. When LLMs are prompted with generic descriptors ("clean," "modern," "premium SaaS"), they generate the statistical median across millions of training templates: centered heroes, Inter typography, purple-to-blue linear gradients, 1px gray card borders, and generic aspirational copy.

Contradiction Test: What AI Slop IS vs. IS NOT

Single visual choices do not signal algorithmic generation in isolation. Slop is an aggregate property resulting from unconstrained statistical defaults and a lack of human art direction.

Inter / Geist Fonts

NOT Slop: When paired intentionally across clear typographic scales.

IS Slop: Applied indiscriminately across H1-H6 and body without font pairing.

Rounded Cards

NOT Slop: Basic layout primitives used for content grouping.

IS Slop: Uniformly applied everywhere resulting in "cardocalypse" (cards in cards).

Dark Mode & Gradients

NOT Slop: Valid visual styles for developer platforms or media apps.

IS Slop: Automatic fallback to #09090b with cyan/violet neon glows regardless of brand.

shadcn/ui & Tailwind

NOT Slop: Modern front-end primitives designed for customization.

IS Slop: Shipping un-themed default utility classes with stock gray borders.

The 4-Layer Instruction Hierarchy

To maintain anti-slop rules permanently without cluttering every conversational prompt, separate design requirements across four operational layers.

Layer 1: Project Memory
CLAUDE.md / DESIGN.md

Permanent design system tokens, font stacks, prohibited gradients, and color caps stored at project root.

Layer 2: Targeted Rules
.claude/rules/ui.md

Granular coding rules enforcing borderless card defaults, Tailwind restrictions, and APCA contrast checks.

Layer 3: Reusable Skills
/skills/design-qa

Automated procedures that run DOM style extraction and contrast verification before code commits.

Layer 4: Session Prompts
Task-Specific Inputs

Focuses purely on feature requirements, relying on Layers 1–3 to carry visual boundaries automatically.
